# Le registre des outils : les quatre robots

À recopier dans le registre des outils du club (dossier du club), une fiche par robot.
Les champs « à compléter » sont à remplir en bureau avant de passer le mode essai à « non ».

| | Rappels des obligations | Veille des appels | Site du club | Robot de garde |
|---|---|---|---|---|
| **Type** | Automatisation | Automatisation (IA facultative) | Automatisation | Automatisation |
| **Où tourne-t-il ?** | Dépôt GitHub au nom du club | Dépôt GitHub au nom du club | Dépôt GitHub au nom du club | Dépôt GitHub au nom du club |
| **Outil** | GitHub Actions | GitHub Actions, API d'IA | GitHub Actions, GitHub Pages | GitHub Actions |
| **Données utilisées** | Dates et rôles, aucune donnée personnelle | Pages publiques, fiche publique du club | Matchs, horaires, lieux, scores | État des robots |
| **Arbitre** | Le rôle désigné sur chaque ligne | Trésorier | Tenue du tableau des matchs | Administrateurs du dépôt |
| **Responsable** | _à compléter_ | _à compléter_ | _à compléter_ | _à compléter_ |
| **Personne de secours** | _à compléter_ | _à compléter_ | _à compléter_ | _à compléter_ |
| **Derniers tests** | _date_ | _date_ | _date_ | _date_ |
| **Plan B, à la main** | Relire le tableau le 1er du mois | Consulter la liste des sources | Annoncer sur les réseaux | Regarder l'onglet Actions |
| **Surveillance** | Robot de garde | Robot de garde | Robot de garde | Vérification humaine mensuelle |
| **Prochaine revue** | _date_ | _date_ | _date_ | _date_ |

## Les accès

| Qui | Rôle sur GitHub | Pourquoi |
|---|---|---|
| _à compléter_ | Propriétaire (owner) de l'organisation | Responsable des robots |
| _à compléter_ | Propriétaire (owner) de l'organisation | Personne de secours : deux propriétaires, toujours |
| _à compléter_ | Écriture (write) sur le dépôt | Met à jour les tableaux |

Quand un bénévole quitte le club : retirez son accès le jour même, et changez les secrets qu'il connaissait (mot de passe de messagerie, clé d'API).
